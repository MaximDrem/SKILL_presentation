# Page-spec DSL — контракт JSON (v1)

Контракт между вами (автор `pages/*.json`) и `deck.cjs check/build`. Одна
страница = один файл `pages/slide-NN.json`. Правила процесса (порядок шагов,
правки, доставка) — не здесь, а в SKILL.md и вашем workflow-файле. Этот файл
— только грамматика и проверки.

## 1. Общие правила

- Канвас **1280×720 px, целые**. z-order = порядок в `elements` (первый —
  нижний).
- Лимиты: ≤48 элементов/страница, ≤8 картинок/страница, ≤60 страниц.
- Цвет: `#RRGGBB` или `#RRGGBBAA` (альфа в hex) или градиент-объект (§6) —
  для заливок и для цвета текста одинаково.
- `bounds: [x, y, w, h]` px. Выход за канвас или отрицательные x/y — только
  с `bleed: true`.
- Везде px. EMU — внутреннее дело build.

## 2. Страница

```json
{
  "pageType": "cover|content|divider|closing",
  "background": { "type": "solid", "color": "#060E10" },
  "elements": [ ]
}
```

- `pageType` — роль страницы (cover первой, closing последней).
- `proto` — номер слайда-прототипа. Наследуется ТОЛЬКО фон прототипа
  (`p:bg`, фон лэйаута, полноэкранные фоновые картинки): в CLONE — всегда;
  в CREATE — только при `--theme dark|light` (без `--theme` дека собирается
  на пустом пакете, и странице нужен свой явный `background`). Для CREATE с
  темой фон выбирается через `templates/default-ref/slides.md`.
  Логотип и decor агент добавляет самостоятельно как отдельные элементы. Прочие
  объекты прототипа не копируются никогда. Доступны только proto из таблицы
  «## Contents» вашего атласа; degraded-прото отклоняется с дефолтной
  заменой в тексте фейла. Без `proto` build подбирает автоматически.
- `background` — явный фон страницы (перекрывает унаследованный):
  `{ "type": "solid", "color": "#060E10" }` |
  `{ "type": "image", "src": "media/bg.jpg", "fit": "fill" }` |
  `{ "type": "gradient", "gradient": {…} }`.
  В CLONE не задаётся. Не элемент — не входит в лимит 48.

## 3. Элементы — общие поля

| Поле | Тип | Дефолт | Правила |
|---|---|---|---|
| `type` | `"shape"\|"text"\|"image"\|"chart"\|"table"` | — | обязательно |
| `bounds` | `[x,y,w,h]` int | — | обязательно; между соседними текстовыми боксами ≥16px |
| `rotation` | ° float | 0 | по часовой |
| `opacity` | 0..1 | 1 | |
| `flip` | `{"h":bool,"v":bool}` | — | |
| `bleed` | bool | false | разрешает выход за канвас |
| `id` | string | позиционный | стабилен: при правке страницы id существующих элементов не менять |

`name` не задавать — генерируется build'ом.

## 4. Типы элементов

**shape:**
```json
{ "type": "shape", "shape": "roundRect", "adjustments": [6000],
  "bounds": [58, 198, 360, 311],
  "fill": { "solid": "#0A4B6763" },
  "line": { "w": 1, "color": "#34D3FF" },
  "shadow": "soft" }
```
- `shape`: 21 пресет (rect, roundRect, ellipse, arrows, chevron, pie,
  donut, star5…). Линии/коннектора нет — линия = тонкий `rect` (h 1–3,
  `fill.solid`, без `line`).
- `fill`: `{ "solid": "#RRGGBBAA" }` | `{ "gradient": {…} }` | `{ "none": true }`.
- `line`: `{ "w": px, "color": "…" }`; нет поля — нет обводки.
- `shadow`: токен `"none"|"soft"|"lift"`; свободные параметры запрещены.

**image:**
```json
{ "type": "image", "src": "media/torus.png",
  "bounds": [234, -810, 1296, 1296], "rotation": 209.28,
  "opacity": 0.43, "bleed": true }
```
- `srcRect`: `{ "l":0.30, "t":0.05, "r":0.16, "b":0 }` — доли 0..1
  (center-crop; искажение пропорций запрещено — см. §5).
- `shadow`: токен, как у shape; только растровые image (не svg).
- `src` может быть `*.svg` (пиктограммы декора шаблона): build вставляет
  нативные векторные фигуры (grpSp из custGeom-путей), не растр. Поддержка:
  `<path>` с абсолютными M/L/C/Z и solid fill (+fill-opacity); srcRect для
  svg нет; rotation/flip/opacity работают.

**chart:**
```json
{ "type": "chart", "bounds": [628, 322, 595, 221],
  "chart": { "kind": "bar",
    "series": [{ "name": "Calls",
      "categories": ["bash", "edit", "read"], "values": [1188, 473, 421] }],
    "colors": ["#00ADEE"], "legend": false, "title": "…" } }
```
- `kind` = `bar|line|pie|doughnut`; данные инлайн; `values`/`categories`
  равной длины. Build делает нативный редактируемый chart.

**table:**
```json
{ "type": "table", "bounds": [53, 154, 1171, 238],
  "table": { "colW": [390, 390, 391],
    "rows": [
      [ {"text": "Parameter", "b": true, "fill": "#F2F5F3"},
        {"text": "Option A", "b": true, "fill": "#F2F5F3"} ],
      [ {"text": "Cost"}, {"text": "low"} ]
    ],
    "font": "Inter", "sz": 14, "color": "#0B0F14",
    "border": { "w": 1, "color": "#DDE3E8" }, "inset": 8 } }
```
- Ячейка: `{ "text", "b"?, "i"?, "sz"?, "color"?, "fill"?, "align"?,
  "colSpan"?, "rowSpan"? }` — перекрывает стиль таблицы.
- `colW` обязателен (px, сумма = bounds.w); все строки одной длины;
  colSpan/rowSpan в пределах сетки.

**text:**
```json
{ "type": "text", "bounds": [45, 59, 713, 40], "anchor": "t",
  "paragraphs": [
    { "runs": [ { "text": "Problem statement", "sz": 32,
                  "font": "Inter", "b": true, "color": "#FFFFFF" } ],
      "align": "l" }
  ] }
```
- run: `{ "text", "sz"?, "b"?, "i"?, "font"?, "color"? }` — color = hex
  или градиент-объект.
- paragraph: `{ "runs", "align": "l|ctr|r|just", "bullet": "none"|"char",
  "bulletChar": "•", "lineHeight": 1.05, "spcBef": pt, "spcAft": pt }`.
- Уровень элемента: `anchor`: `"t"|"ctr"|"b"`; `autofit`: `"none"|"norm"`
  (`spAutoFit` ЗАПРЕЩЁН — растит бокс поверх соседей; «norm» — только по
  явной просьбе пользователя, никогда как реакция на HARD).
- Стиль задаётся явно на каждом run (sz/font/color/b/i) — темовых ссылок
  нет. Значения копируются из атласа (дефолтный шаблон: «## Цвета и фоны»
  вашей темы; клон-атлас: «## Style»).

## 5. Text-fit и перекрытия (что фейлит build)

- Оценка высоты текста больше высоты бокса на >8% (многострочные; одна
  строка терпит до +40%), либо токен шире бокса (перенос посреди слова) —
  `[HARD]`. Оценка откалибрована по SB Sans.
- Перекрытие боксов: текст наезжает на текст или на не-фоновую картинку —
  `[HARD]` (см. overlap: элемент с `bleed: true` освобождает пару).
- Картинка растянута по пропорциям >30% — `[HARD]`; >8% — обязательный WARN.
- Каждый фейл несёт дефолтное действие в `action` и план в `plan[]`
  конверта — применяйте как напечатано, не пересчитывайте.
- Боксы давайте с запасом высоты; точные числа даёт `check`, в уме не
  считайте.
- Альфа <90% в стопах градиента рендерится по-разному в LO/P7/приложении —
  предпочитайте solid с альфой или непрозрачный градиент к цвету фона.
  Альфа заливки <10% почти невидима.

## 6. Градиент-объект

```json
{ "angle": 45, "stops": [[0, "#62ECFF"], [0.45, "#1EB8AD"], [1, "#43C690"]] }
```
- Линейный, `angle` в °, stops = `[pos 0..1, "#RRGGBB(AA)"]`, 2–4 стопа.

## 7. Запрещено (валидация отклоняет)

- Свободные параметры тени (только токены); `spAutoFit`.
- `name`, `placeholder` на элементах; смена `id` существующих элементов.
- `src` вне `media/` проекта; сгенерированные картинки в CLONE (там только
  побитовые копии из атласа референса).
- wmf/emf/wdp как источники image; svg — только в подмножестве §4.
- Эмодзи/пиктограммы в тексте (¶, ✓, 🛡, стрелки) — рендерятся тофу;
  типографские символы (— – « » • … ₽) можно.
- Плейсхолдеры в тексте: regex `XX%|lorem|TBD|{{`.
- SmartArt/видео/OLE/combo-чарты и пр. — страницы-источники с
  `coverageReport.unrecognized` не пересобираются; degraded-прото
  отклоняется с дефолтной заменой (§2).

## 8. Уместность декора

- `picto-*.svg` — иконки для слотов: центры бейджей, маркеры, мелкие акценты
  (≤96px); никогда не главный визуал слайда.
- 3D-иллюстрация — максимум одна на слайд, только главный/hero-визуал в
  отдельной зоне и только при прямой связи с основной идеей слайда. Не использовать 3D как
  заполнение пустого места или как иконку отдельной карточки/буллета.
- SVG-пиктограмма — смысловой маркер конкретного тезиса, карточки или шага.
  Выбирать её по смыслу текста элемента, а не как декоративный акцент.
- Внутри одной повторяющейся сетки карточек все смысловые иконки должны
  принадлежать одной визуальной семье. Не заменять одну SVG-иконку сетки
  на 3D-иллюстрацию.
- Не изображать одно и то же понятие на одном слайде одновременно в 3D и SVG.
  3D-hero и SVG-маркеры должны иметь разные смысловые роли и занимать разные
  зоны слайда.
- Если подходящей по смыслу 3D-иллюстрации нет — убрать её или заменить на
  SVG/нативную фигуру, а не ставить произвольную 3D для заполнения.
- Фото/полноэкранные картинки — только из медиа пользователя или генерации
  (CREATE) / из медиа референса (CLONE); пиктограмму в фото-слот не ставить.
- CLONE: сначала декор референса; встроенные пиктограммы — только если у
  референса самого плоские иконки/svg.
- Копируется только НЕЙТРАЛЬНЫЙ декор (абстракции, блобы, кольца, стекло,
  текстуры, универсальные иконки). Не копируется чужой контент: скриншоты
  UI, фото людей, чужие диаграммы/логотипы/QR — это несёт чужой смысл.

## 9. Что проверяет валидация

- Схема/типы/лимиты (§1–§4): обязательные поля, enum'ы, unknown fields,
  уникальные `id`.
- Ресурсы: каждый `src` существует в media/; `srcRect` в 0..1.
- Чарты/таблицы — правила §4.
- Стиль (палитра/типографика) НЕ проверяется — это ваша зона.
- Ошибка валидации — конверт `{error, plan[], failures[], suggestion}`;
  при фейле ничего не собирается.
